# 无线麦 Mac 版：构建与安装说明

把 Chromecast 语音遥控器（G9N9N）变成 Mac 的无线麦克风与遥控器。
本页只讲“怎么从源码打一个能装的包”，应用本身的用法见工程 README。

## 环境要求

- macOS 14 或更高版本的 Mac（Apple Silicon 或 Intel 均可）。
- 只需要 Xcode 命令行工具（`/usr/bin/swift`），**不需要 Xcode.app**。
  没有装过的话，先跑一次：
  ```sh
  xcode-select --install
  ```
- 本应用**不是沙盒应用**（设计如此）：它需要 IOKit 读取遥控器按键、
  需要 CGEvent 模拟按键，所以打包时不加沙盒 entitlements。
  首次启动时系统会分别弹窗要蓝牙与辅助功能权限，都允许即可。

## 一、构建

在工程根目录（`wirelessmic-mac/`）下跑：

```sh
zsh packaging/build.sh
```

脚本会依次做：检查 swift → `swift build -c release` → 组装
`WirelessMic.app` → 签名 → 校验 → 生成 DMG 与 zip → 安装到
`/Applications/WirelessMic.app`（固定路径，见下面“授权只需一次”）。
每一步失败都会打印中文原因和下一步建议，不用猜。

产物都在 `dist/`：

| 文件 | 说明 |
| --- | --- |
| `dist/WirelessMic.app` | 应用包，可直接运行 |
| `dist/WirelessMic.dmg` | 安装镜像（推荐，卷名“无线麦”） |
| `dist/WirelessMic.zip` | 备选压缩包 |

### 授权只需一次：固定签名身份 + 固定安装路径

每次构建后都要重新授权，原因不在应用本身，在签名：

- 系统是按**签名身份**认应用的。ad-hoc 签名（`codesign --sign -`）
  没有固定身份，每次构建签名都会变，系统就把每个新构建当成一个
  新应用，蓝牙 / 输入监控 / 辅助功能全部重新弹窗。
- 固定证书签名后，签名身份不变，授权只需给一次，之后构建都不用再授权。
  安装路径也要固定（总在 `/Applications/WirelessMic.app`），不要每次
  从 Downloads 的新解压文件夹里启动旧包。

**只做一次：创建本地签名证书**

1. 打开“钥匙串访问”。
2. 菜单栏：钥匙串访问 → 证书助理 → 创建证书…。
3. 名称填 `WirelessMic Local`；身份类型选“自签名根证书”；
   证书类型选“代码签名”；勾选“让我覆盖默认设置”，点继续。
4. 有效期填 `3650`（天，约 10 年，省得过期重来），后面一路继续
   （密钥 2048 位默认即可），完成。
5. 左侧选“登录”钥匙串 →“我的证书”，能看到 `WirelessMic Local` 就成了。

之后再跑 `zsh packaging/build.sh`，脚本会自动用这个证书签名。
签名时钥匙串会弹一次“codesign 想访问钥匙串”，点**“始终允许”**，
以后构建就不再弹这个。

**注意：换签名后第一次还要授权一次**（因为签名身份换了，系统认成
新应用），允许后，之后每次构建都不用再授权了。第一次启动如果被
Gatekeeper 拦下（“无法验证开发者”），右键 → 打开，放行一次即可，
之后正常双击启动。

不想用证书、或跳过自动安装时：

- 仍用 ad-hoc 签名：每次构建都会重新授权，这是 ad-hoc 本身的限制，无解。
- 跳过自动安装：跑之前设置 `WIRELESSMIC_NO_INSTALL=1 zsh packaging/build.sh`，
  然后手动把 DMG 里的应用拖到 Applications 替换（路径也要固定）。
- 指定别的证书：`WIRELESSMIC_SIGN_IDENTITY="证书名" zsh packaging/build.sh`。

### 可选：图标

图标不是必需的，没有图标也能正常构建与运行。想要图标的话：

1. 准备一张 1024x1024 的 PNG，放到 `packaging/AppIcon.png`（自己画或找图均可）。
2. 跑：
   ```sh
   zsh packaging/icon.sh
   ```
   它会用系统自带的 `sips` + `iconutil` 生成 `packaging/AppIcon.icns`。
   PNG 不存在、或本机没有 `iconutil` 时，脚本会明确提示并跳过，
   不会报错中断。
3. 再跑一次 `zsh packaging/build.sh`，图标会自动拷进应用包。

## 二、安装

`build.sh` 跑完默认已经自动装到 `/Applications/WirelessMic.app`
（除非设置了 `WIRELESSMIC_NO_INSTALL` 跳过）。以后每次构建都会
自动装到同一个固定路径，直接从启动台或 `/Applications` 启动它，
不要再从 Downloads 的解压文件夹里启动旧包。

如果跳过了自动安装，再手动装：

1. 打开 `dist/WirelessMic.dmg`，把里面的“无线麦.app”拖到 Applications。
2. **首次启动请右键 → 打开**：自签名证书和 ad-hoc 签名都会触发一次
   Gatekeeper 提示，直接双击会被拦下，右键打开点一次“打开”即可放行。
   之后正常双击就能启动。
3. 去“系统设置 → 隐私与安全性”里允许权限：
   - **蓝牙**：连接 Chromecast 语音遥控器用。拒绝的话应用找不到遥控器。
   - **辅助功能**：模拟按键用（把遥控器按键变成键盘操作）。
   - **输入监控**：读取遥控器按键用（遥控器在系统里是一只 HID 设备）。
   如果首次启动时没弹权限窗，去上面几个位置手动把“无线麦”加进去，
   再重启应用。

## 三、单独安装 BlackHole 虚拟麦克风

本应用不自带虚拟麦克风，声音要经过虚拟麦克风才能进输入法，
需要另外装一次 BlackHole（免费开源）：

- 去 GitHub 官方仓库 **ExistentialAudio/BlackHole** 下载安装包，
  按仓库里的说明安装（一般是 2ch 版就够）。
- 装完重启一次 Mac，再回到无线麦里选 BlackHole 作为输出。

## 四、遥控器

- 之前在终端跑过 v0 验证（`chromecast-v0.swift`）的用户：
  已经配对验证过的遥控器可以直接复用，不用重新配对——
  打开无线麦，它会在系统已连接设备里找到同一只遥控器。
- 新遥控器：先在系统蓝牙设置里配对（遥控器进配对模式后，
  在 Mac 蓝牙列表里选中连接），再打开无线麦。
- 型号提醒：谷歌遥控器版本多，不能只凭外观判断兼容性，
  以电池仓内的型号为准（已验证的型号是 G9N9N）。

## 常见失败排查

- **提示没有 swift / `swift` 不存在**
  没装命令行工具：跑 `xcode-select --install`，装完重新打开终端再跑。
- **编译失败（`swift build` 报错）**
  先看报错本身，多半是 Sources 里的 Swift 编译错误；
  修好源码再跑 `zsh packaging/build.sh`。跟打包脚本无关。
- **签名失败（`codesign` 报错）**
  ad-hoc 签名不需要开发者证书。先确认 4/9 组装那步成功了、
  应用包完整；仍失败就删除 `dist/` 后重跑一次。
- **DMG 打不开 / 提示已损坏**
  先确认 DMG 下载完整；删掉重新跑一次构建。
  ad-hoc 签名偶尔会被 Gatekeeper 误报，删掉应用后重新拖入、
  再用右键 → 打开放行一次。
- **蓝牙权限被拒，应用找不到遥控器**
  去“系统设置 → 隐私与安全性 → 蓝牙”里允许“无线麦”；
  如果列表里没有它，重启应用触发一次权限弹窗再允许。
  还要确认遥控器已开机、在 Mac 附近、在系统蓝牙里可见。
- **按键映射不起作用**
  多半是辅助功能权限没给：去“系统设置 → 隐私与安全性 →
  辅助功能”里允许“无线麦”，再重启应用。
- **没有图标也能用吗**
  能。图标只是外观，`build.sh` 没找到 `AppIcon.icns` 时会提示
  并跳过，不影响构建与运行。
- **zip 备选没生成**
  只要 DMG 生成了就不影响使用；zip 只是备选，
  失败时脚本会打印警告并继续，不会让整个构建失败。
